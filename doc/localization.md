# Localization

Reader display-copy keys from `assets/en.strings`, utility/game text and website copy are covered by the language catalogs in `assets/translations/`. `languages.json` defines the selectable languages, using `ku` for Latin-script Kurdish (Kurmancî); `kmr`, `nb` and `nn` are normalized to `ku` and `no`. Unsupported languages use English.

These catalogs are machine-translated drafts, generated from the public UI copy with Google Translate in November 2026. They need native-speaker review, especially technical warnings and Kurmancî wording. Structural checks do not establish linguistic correctness. Names, file paths, process output, book content, upstream license notices and operating-system errors are intentionally not rewritten.

`source.json` holds the complete source inventory. Reader sources mirror the canonical English `.strings` file. Utility and website sources currently use the existing German copy as their lookup keys. Preserve keys and `%1` style argument slots when editing a translation. Each language must contain every source entry. There is no runtime translation API and no remote script or font dependency.

The reader loads embedded Qt resources through `src/support/localization.h`; all desktop, Kobo Qt5/Qt6 and Android platform resource lists include the same catalogs. Catalog files are separate from the runtime font/hyphenation manifest and do not change stored-reading formats. The optional `ui_language` preference uses the existing settings writer and applies when opening the next book. Existing screens are deliberately not rebuilt while a reader is in use. Missing or invalid language codes default to the device language or English. Missing individual translations fall back to English.

The website detects browser language, supports `?lang=ku` links, and remembers an explicit choice in local storage when available. Language changes reload the page and require selecting the device again; the selector is disabled during copying. Both Pages and the Windows bundle ship `locale.js` and local catalogs. The PowerShell server exposes only its explicit read-only routes. Installation, update detection, archive verification and rollback keep the same implementation in every language.

Run `node tests/localization.test.mjs` for inventory and placeholder validation, `node tests/installer.site.test.mjs` for static packaging and `node tests/installer.browser.mjs` with Playwright for browser flows in every language. The native utilities tests exercise each embedded catalog, translated controls, formatting and fallback. Reader settings keep the language optional so old profiles continue to load. Inspect multilingual screenshots for text expansion in addition to these functional checks. Physical-device font coverage and translation quality still require device/native-speaker review.
